# FR-007 — Full legacy HTML-to-Next route migration

**Labels:** `Future`, `migration`, `routes`

## User Story
As a maintainer, I want the remaining static HTML pages migrated into typed App Router pages, so that the app has consistent routing and maintainability.

## Proposed Solution
Create a route migration matrix and move legacy pages in batches after the MUS deployment is stable.

## Implementation Flow
1. List all `pages/*.html` files and map to desired Next routes.
2. Prioritize high-traffic/user-visible pages.
3. Extract shared patterns into components.
4. Retire legacy HTML once parity is verified.

## Technical Approach
- Use feature/page batches rather than one giant migration.
- Add redirects for old static paths if needed.

## Key Considerations
- Full migration is not required before first working Vercel/PWA milestone.

## Acceptance Criteria
- [ ] Migration matrix exists.
- [ ] Each legacy page has target route/status.
- [ ] Migrated pages share common components.
- [ ] Legacy files are retired only after parity.
