# FR-003 — Preserve and stabilize the existing public-facing Fidelity-style UI

**Labels:** `MUS`, `ui`, `migration`, `stability`

## User Story
As a user, I want the existing pages and navigation to remain usable after cleanup, so that the salvage does not discard prior work.

## Proposed Solution
Preserve the current Next.js homepage and migrate/repair the most important static pages incrementally, starting with links currently visible in the navigation and homepage.

## Implementation Flow
1. Audit broken links and missing routes from `nextjs-app/app/page.tsx`.
2. Create placeholder-safe pages for critical routes if full migration is not complete.
3. Move required images/assets into `nextjs-app/public` with stable paths.
4. Split oversized components into smaller sections over time.

## Technical Approach
- Use App Router pages under `nextjs-app/app/**/page.tsx`.
- Prefer shared layout components for header/footer.
- Use typed route config from `config/routes.ts` where possible.

## Key Considerations
- This appears to be a Fidelity-style mockup; avoid implying production affiliation if not authorized.
- Preserve visual work while improving structure.

## Acceptance Criteria
- [ ] Homepage renders without missing critical assets.
- [ ] Primary navigation links do not dead-end unexpectedly.
- [ ] Broken routes are either implemented or clearly safe placeholders.
- [ ] Build and type-check pass.
