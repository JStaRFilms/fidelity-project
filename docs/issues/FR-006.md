# FR-006 — Verification and deployment checks

**Labels:** `MUS`, `quality`, `ci`, `verification`

## User Story
As a maintainer, I want repeatable local checks for type-check, lint, build, and PWA assets, so that deployments are predictable.

## Proposed Solution
Use `scripts/vibe-verify.py` as the handoff gate and root-level pnpm scripts as the Vercel-compatible deployment entry point.

## Implementation Flow
1. Confirm verification commands from canonical app root.
2. Run TypeScript, lint, and build checks.
3. Add PWA asset/manifest checks if needed.
4. Document failures and fixes before deployment.

## Technical Approach
- From `nextjs-app/`: `npx tsc --noEmit`, `pnpm lint`, `pnpm build`.
- From repo root: `pnpm build` proxies to `nextjs-app`; `python scripts/vibe-verify.py` verifies the app package directly.

## Key Considerations
- The root `package.json` must expose Next.js dependencies so Vercel can detect the framework from repository root.
- pnpm is the intended package manager; npm lockfiles were removed to prevent Vercel/npm confusion.
- Do not claim done while build is failing.

## Acceptance Criteria
- [x] Verification script exists.
- [x] Verification target/root is documented.
- [x] Type-check, lint, and build commands are known.
- [x] Deployment readiness is reproducible.
