# FR-001 — Repository architecture cleanup and canonical app root

**Labels:** `MUS`, `architecture`, `vercel`, `cleanup`

## User Story
As a maintainer, I want one clearly documented deployable Next.js app root, so that Vercel builds the real application instead of a wrapper or placeholder.

## Proposed Solution
Make `nextjs-app/` the canonical application. Keep legacy root HTML/backend folders as reference until migration is complete, but stop treating the root wrapper as the deployable product.

## Implementation Flow
1. Audit root `package.json`, `index.html`, `nextjs-app/package.json`, and Vercel project settings.
2. Document the canonical root and local commands.
3. Add/adjust Vercel configuration if needed so builds run from `nextjs-app/`.
4. Remove or bypass placeholder UI that tells users to start a local server.

## Technical Approach
- Vercel Project Settings: Root Directory = `nextjs-app`.
- Build command: `npm run build` or package-manager equivalent from `nextjs-app`.
- Output: Next.js default, not static wrapper.

## Key Considerations
- Avoid deleting legacy files before route parity is confirmed.
- Lockfile/package-manager conflicts should be resolved deliberately.

## Acceptance Criteria
- [x] The deployable app root is documented.
- [x] Vercel builds `nextjs-app/` through root-level pnpm proxy scripts.
- [ ] The deployed app no longer shows the “Next.js server not found” placeholder.
- [x] Local run instructions are accurate.

## Progress Notes
- Root `package.json` now exposes Next.js dependencies for Vercel framework detection and proxies scripts to `nextjs-app/` with pnpm.
- Root `vercel.json` now uses `pnpm install` and `pnpm build` instead of manual `cd nextjs-app && npm ...` commands.
- Root `pnpm-workspace.yaml` declares `nextjs-app` as the workspace package.
- Root `pnpm build` passes locally.
