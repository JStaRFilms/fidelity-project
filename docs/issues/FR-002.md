# FR-002 — Vercel serverless deployment compatibility

**Labels:** `MUS`, `backend`, `serverless`, `api`

## User Story
As a maintainer, I want the backend behavior converted from a long-running Express server to serverless-compatible Next.js route handlers, so that the app deploys successfully on Vercel.

## Proposed Solution
Port only the MUS backend endpoints from `backend/src/server.js` and related route modules into `nextjs-app/app/api/**/route.ts`.

## Implementation Flow
1. Inventory Express routes and middleware.
2. Decide which endpoints are MUS vs future.
3. Recreate MUS endpoints as Next.js route handlers.
4. Replace frontend calls to `localhost:5000` with same-origin `/api` calls.
5. Verify on Vercel-compatible build.

## Technical Approach
- Use `app/api/health/route.ts`, `app/api/auth/.../route.ts`, etc.
- Replace Express middleware with per-route helpers.
- Use Zod for validation.
- Use serverless-safe DB connection helpers if persistence is retained.

## Key Considerations
- No `app.listen()` in Vercel serverless.
- Environment variables must be available in Vercel.
- Rate limiting in serverless may need a hosted store, not in-memory counters.

## Acceptance Criteria
- [ ] No deployed flow depends on a persistent Express server.
- [ ] MUS API endpoints exist under `nextjs-app/app/api`.
- [ ] Frontend API calls use same-origin `/api` paths.
- [ ] Production build succeeds.
